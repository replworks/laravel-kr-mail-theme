# PRODUCT_SPEC.md

## Purpose

- Package: replworks/laravel-kr-mail-theme, a Laravel mail theme package for Korean-market services.
- Service: a Laravel application that uses the Package.
- Developer: a person who builds a Service and installs the Package.
- Recipient: a person who receives a mail rendered with the Package.
- Theme: the single built-in mail layout provided by the Package.
- Mail Body: the content between header and footer, written in Markdown and supplied by the Service.
- Brand Information: the set of values that identify the Service in a mail (see Inputs).
- Placeholder: the value the Package shows for Service Name or Logo when it is not supplied (see Inputs).
- Recipient Name: the name of the Service user who receives the mail. Optional.
- Recipient Display Name: the form of the Recipient Name that a Mail Body shows (see Inputs).
- Rendered Mail: the HTML part and the TEXT part produced from the Theme, a Mail Body, and Brand Information.
- HTML part: the HTML version of a Rendered Mail.
- TEXT part: the plain text version of a Rendered Mail.
- Informational Mail: a mail that does not contain advertising content.
- Advertising Mail: a mail that contains advertising content.
- Unsubscribe Link: the signed URL generated by the Package that unsubscribes one Service user from Advertising Mail.
- Consent Record: a record kept by the Package that links one Service user identifier to one boolean marketing consent value.
- Unsubscribe Event: the event fired by the Package after a marketing consent value changes to false.
- Workbench: the browser-based screen provided by the Package repository for previewing and test-delivering Rendered Mail. It is a development tool and is not installed in a Service.
- Sample Body: one of four fixed Mail Bodies provided by the Workbench: receipt-style table, button, long paragraph, quotation.
- The Package provides the header, footer, and unsubscribe area of every Rendered Mail.
- The Package provides the HTML part and the TEXT part from one Mail Body.
- The Package provides the processing of Unsubscribe Link requests.
- The Service provides the Mail Body wording.

## Problem

- Mail layout code is placed inside each Service.
- Mail layout code is rewritten for each Service.
- A Service that sends HTML mail makes the person responsible for sending also responsible for the design.
- A Service that sends HTML only gives Recipients on text-oriented devices a poor mail.
- Mail layout verification across mail clients is performed inside each Service.
- Unsubscribe link handling is written inside each Service.

## Product Goals

- The Package enables the Developer to apply a Korean-market mail layout to a Service by installing the Package and writing the Mail Body in Markdown.
- The Package enables the Developer to supply Brand Information through environment variables or a configuration file, and to send mail before supplying it.
- The Package enables the Developer to send every mail as an HTML part and a TEXT part without writing either.
- The Package enables the Developer to preview Rendered Mail in a browser.
- The Package enables the Developer to deliver a test mail to Mailpit from a browser.
- The Package enables the Developer to verify layout compatibility, TEXT part content, and footer completeness through automated checks.
- The Package enables the Developer to send Advertising Mail with the required subject prefix and a working Unsubscribe Link without writing layout code or unsubscribe handling code.
- The Package enables the Developer to react to an unsubscribe by listening to the Unsubscribe Event.

## Users

- Developer: the only user who operates the Package.
- Recipient: opens the Unsubscribe Link. MUST NOT operate any other part of the Package.

## Inputs

- Mail Kind: Informational Mail or Advertising Mail. Declared per mail by the Service.
- Mail Subject: supplied per mail by the Service.
- Mail Body: Markdown, supplied per mail by the Service as a Blade view that outputs Markdown.
- Recipient User Identifier: the identifier of the Service user who receives the mail. Supplied per mail by the Service. Required for Advertising Mail. Not used for Informational Mail.
- Recipient Name: supplied per mail by the Service. Optional for both Mail Kinds. Not supplied when it is unset or an empty string.
- Recipient Display Name: the Recipient Name followed by `님` when supplied, and `회원님` when not supplied. The Package makes it available to the Mail Body.
- Brand Information fields, all optional for both Mail Kinds. A field is not supplied when it is unset or an empty string.
  - Service Name. Placeholder: `[서비스명]`.
  - Logo: an absolute image URL. Placeholder: the text `[로고]`, shown in the position of the Logo.
  - Company Name. No Placeholder. Not shown when not supplied.
  - Customer Center Contact. No Placeholder. Not shown when not supplied.
  - Business Registration Number. No Placeholder. Not shown when not supplied.
  - Address. No Placeholder. Not shown when not supplied.
  - Terms Link: an absolute URL. No Placeholder. Not shown when not supplied.
- Brand Information source: environment variables, or one configuration file of the Service. When both supply a value for a field, the configuration file value is used.
- Unsubscribe Path: the URL path of the Unsubscribe Link. Supplied through configuration or an environment variable. Default value: unsubscribe.
- Unsubscribe request: a GET request or a POST request to an Unsubscribe Link, made by a Recipient or by a mail client.
- Workbench Recipient Address: an email address entered in the Workbench.
- Workbench Mail Kind, Sample Body, Viewport, and Color Scheme: selections made in the Workbench.
- Workbench Brand Information: a fixed sample set in which every Brand Information field is supplied.
- Workbench Recipient User Identifier: a fixed sample value.
- Workbench Recipient Name: a fixed sample value.

## Outputs

- HTML part structure: header, Mail Body, footer, in this order.
- TEXT part structure: Service Name, Mail Body, footer content, in this order.
- Header content: Service Name and Logo, or their Placeholders.
- Footer content of both Mail Kinds: each supplied field among Company Name, Customer Center Contact, Business Registration Number, Address, Terms Link. A field that is not supplied is not shown.
- Advertising Mail footer content: the footer content of both Mail Kinds, and the Unsubscribe Link.
- Mail Body conversion: Markdown paragraphs, links, tables, and blockquotes appear as their HTML equivalents in the HTML part and as plain text in the TEXT part. A paragraph that consists only of one link appears as a button in the HTML part and as the link text and URL in the TEXT part.
- Final Subject of Informational Mail: the Mail Subject.
- Final Subject of Advertising Mail: the literal "(광고)", one space, and the Mail Subject.
- Advertising Mail header List-Unsubscribe: the Unsubscribe Link.
- Advertising Mail header List-Unsubscribe-Post: the value List-Unsubscribe=One-Click.
- Response to a GET Unsubscribe request: SCR-002.
- Response to a POST Unsubscribe request: an HTTP status and no screen.
- Consent Record: one boolean marketing consent value per Recipient User Identifier.
- Unsubscribe Event: carries the Recipient User Identifier.
- Workbench output: SCR-001.
- Test Delivery output: one mail, with an HTML part and a TEXT part, delivered to Mailpit.
- Automated check output: one pass or fail result per combination of Mail Kind and Sample Body.

## Constraints

- Supported Laravel versions: 12 and 13.
- Supported PHP versions: the versions supported by Laravel 12 and Laravel 13.
- Target mail clients: Gmail web, Gmail mobile app, Naver Mail web, Naver Mail mobile app, Daum Mail.
- Rendered Mail MUST support a dark color scheme.
- Rendered Mail MUST support a narrow viewport.
- Consent Records MUST be kept across sessions until changed.
- Offline behavior: None stated.
- Performance: None stated.
- Accessibility: None stated.

## External Systems [UNVERIFIED]

- Mailpit: receives Test Delivery mail over SMTP.
- Mailpit: provides a web interface that lists received mail.
- Mailpit: provides an HTML check result per received mail.
- Mailpit: provides received mail content (HTML part and TEXT part) and headers to the automated checks.
- Gmail and Apple Mail: show an unsubscribe control from the List-Unsubscribe header.
- Gmail and Apple Mail: send a POST request with the body List-Unsubscribe=One-Click to the Unsubscribe Link when the control is used.

## User Interface [UNVERIFIED]

Graphical surfaces:

- SCR-001
  - ID: SCR-001
  - Purpose: preview Rendered Mail and trigger Test Delivery.
  - Arrangement: selectors EL-001 to EL-004 are grouped at the top. EL-005, EL-006, and EL-007 follow in that order. EL-008, EL-009, EL-010, and EL-011 are grouped at the bottom.
  - Elements:
    - EL-001: Mail Kind selector. Purpose: select Mail Kind. User action: choose Informational Mail or Advertising Mail.
    - EL-002: Sample Body selector. Purpose: select Sample Body. User action: choose one of the four Sample Bodies.
    - EL-003: Viewport selector. Purpose: select preview width of EL-006. User action: choose Full width or Mobile width. Full width is the width of EL-006. Mobile width is 375 px.
    - EL-004: Color Scheme selector. Purpose: select the color scheme of the preview in EL-006. User action: choose Light or Dark.
    - EL-005: Subject display. Purpose: show the Final Subject for the current selections. User action: none.
    - EL-006: HTML preview area. Purpose: show the HTML part for the current selections. User action: scroll.
    - EL-007: Text preview area. Purpose: show the TEXT part for the current selections as plain text. User action: scroll.
    - EL-008: Recipient Address input. Purpose: receive the Workbench Recipient Address. User action: type an email address.
    - EL-009: Send Test button. Purpose: start Test Delivery. User action: activate.
    - EL-010: Delivery Result indicator. Purpose: show the state of the latest Test Delivery. User action: none.
    - EL-011: Mailpit link. Purpose: open the Mailpit web interface. User action: activate.
  - States:
    - Initial: EL-001 is Informational Mail. EL-002 is receipt-style table. EL-003 is Full width. EL-004 is Light. EL-006 shows the HTML part. EL-007 shows the TEXT part. EL-008 is empty. EL-009 is disabled. EL-010 is hidden.
    - Loading: EL-006 and EL-007 show a loading indication while Rendered Mail is produced. EL-009 is disabled.
    - Populated: EL-006 shows the HTML part. EL-007 shows the TEXT part. EL-005 shows the Final Subject.
    - Empty: not applicable.
    - Error: EL-006 shows the error of the failed rendering identified by its ERR ID. EL-007 is empty. EL-009 is disabled.
    - Disabled: EL-009 is disabled when EL-008 is empty, when EL-008 holds an invalid email address, during Loading, during Sending, and during Error.
    - Sending: EL-009 is disabled. EL-010 shows in-progress.
    - Sent: EL-010 shows delivered.
    - Send failed: EL-010 shows failed and the ERR ID of the failure.
  - Navigation:
    - Activate EL-011 -> Mailpit web interface.
  - Interactions:
    - Change EL-001 -> EL-005, EL-006, and EL-007 show the selected Mail Kind.
    - Change EL-002 -> EL-006 and EL-007 show the selected Sample Body.
    - Change EL-003 -> EL-006 is displayed at the selected width.
    - Change EL-004 -> EL-006 shows the selected color scheme variant.
    - Activate EL-009 -> the Rendered Mail currently shown in EL-006 and EL-007 is delivered to Mailpit with the Final Subject shown in EL-005, addressed to EL-008, and EL-010 shows the result. The delivered HTML part is the normal version, not the version forced to Dark by EL-004.
- SCR-002
  - ID: SCR-002
  - Purpose: show the result of a GET Unsubscribe request.
  - Arrangement: the Theme header is above EL-012. The Theme footer is below EL-012.
  - Elements:
    - EL-012: Result message slot. Purpose: tell the Recipient whether the unsubscribe succeeded or failed. User action: none.
  - States:
    - Initial: not applicable.
    - Loading: not applicable.
    - Populated: not applicable.
    - Empty: not applicable.
    - Success: EL-012 indicates that the unsubscribe succeeded.
    - Error: EL-012 indicates that the unsubscribe failed. The failure is identified by ERR-003.
    - Disabled: not applicable.
  - Navigation:
    - None.
  - Interactions:
    - Open a valid Unsubscribe Link -> the unsubscribe is processed and SCR-002 is shown in Success state.
    - Open an invalid Unsubscribe Link -> SCR-002 is shown in Error state.

Non-graphical surface (automated checks):

- Invocation: the Developer runs the Package automated checks.
- Input: none.
- Output: one pass or fail line per combination of Mail Kind and Sample Body, each failed line identifying the failed FR ID.
- Exit behavior: exit code 0 when every check passes. Non-zero exit code when any check fails.

Non-graphical surface (Unsubscribe request):

- Invocation: a GET request or a POST request to an Unsubscribe Link.
- Input: the Unsubscribe Link. A POST request carries the body List-Unsubscribe=One-Click when sent by a mail client.
- Output for GET: SCR-002.
- Output for POST: a success HTTP status when processed. A non-success HTTP status when the Unsubscribe Link is invalid.

## Functional Requirements [UNVERIFIED]

Theme and structure:

- FR-001: The Package MUST provide exactly one Theme. The Package MUST NOT provide a way to select a Theme.
- FR-002: The HTML part MUST contain header, Mail Body, and footer in this order.
- FR-003: The header MUST show Service Name when supplied, and the Service Name Placeholder when not supplied.
- FR-004: The header MUST show Logo when supplied, and the Logo Placeholder in the position of the Logo when not supplied.
- FR-005: The footer of both Mail Kinds MUST show each supplied field among Company Name, Customer Center Contact, Business Registration Number, Address, and Terms Link.
- FR-006: The footer MUST NOT show a field that is not supplied, and MUST NOT show a Placeholder or an empty label for it.
- FR-007: The Service Name Placeholder MUST appear in the TEXT part when Service Name is not supplied. The rules of FR-005 and FR-006 MUST apply to the TEXT part.
- FR-008: A Brand Information field that is not supplied MUST NOT make rendering fail.

Mail Kinds:

- FR-009: The Package MUST provide a layout for Informational Mail.
- FR-010: The Package MUST provide a layout for Advertising Mail.
- FR-011: The Informational Mail layout MUST NOT contain an Unsubscribe Link.
- FR-012: The Informational Mail layout MUST NOT provide a slot for advertising content.
- FR-013: The Advertising Mail footer MUST show the Unsubscribe Link.
- FR-014: The Unsubscribe Link MUST be visible in the Advertising Mail footer at Full width and at Mobile width.
- FR-015: The Unsubscribe Link MUST be visible in the Advertising Mail footer in Light and in Dark.

Unsubscribe Link and headers:

- FR-016: The Package MUST generate the Unsubscribe Link from the Recipient User Identifier.
- FR-017: The Unsubscribe Link MUST be an absolute URL.
- FR-018: The Unsubscribe Link MUST use the Unsubscribe Path.
- FR-019: The Unsubscribe Link MUST be signed so that any alteration of it is detected.
- FR-020: The Unsubscribe Link MUST NOT expire.
- FR-021: The Advertising Mail MUST contain the header List-Unsubscribe with the Unsubscribe Link.
- FR-022: The Advertising Mail MUST contain the header List-Unsubscribe-Post with the value List-Unsubscribe=One-Click.
- FR-023: The Informational Mail MUST NOT contain the header List-Unsubscribe.
- FR-024: The Informational Mail MUST NOT contain the header List-Unsubscribe-Post.

Subject:

- FR-025: The Final Subject of Advertising Mail MUST begin with "(광고)" followed by one space and the Mail Subject.
- FR-026: The Final Subject of Informational Mail MUST equal the Mail Subject.
- FR-027: The Package MUST NOT add a second "(광고)" prefix when the Mail Subject of an Advertising Mail already begins with "(광고)".

Appearance:

- FR-028: The Theme MUST provide a Light variant and a Dark variant.
- FR-029: The HTML part MUST NOT require horizontal scrolling at Mobile width.

Mail Body and TEXT part:

- FR-030: The Package MUST convert the Mail Body from Markdown to the HTML part content.
- FR-031: A Mail Body paragraph that consists only of one link MUST appear as a button in the HTML part.
- FR-032: The Package MUST convert Markdown paragraphs, links, tables, and blockquotes of the Mail Body to their HTML equivalents in the HTML part.
- FR-033: Every Rendered Mail MUST have an HTML part and a TEXT part.
- FR-034: The TEXT part MUST contain Service Name (or its Placeholder), the Mail Body text, and the footer values of the HTML part, in this order.
- FR-035: The TEXT part MUST NOT contain HTML tags or Markdown link syntax. Every URL that appears in the Mail Body MUST appear in full in the TEXT part.
- FR-036: The TEXT part of Advertising Mail MUST contain the Unsubscribe Link.
- FR-037: The TEXT part of Informational Mail MUST NOT contain an Unsubscribe Link.

Installation and configuration:

- FR-038: Applying the Package to a Service MUST NOT require copying any Package file into the Service.
- FR-039: Brand Information MUST be settable through environment variables alone.
- FR-040: Brand Information MUST be settable through one configuration file of the Service. When a field has a value in the configuration file and in an environment variable, the configuration file value MUST be used.

Workbench:

- FR-041: The Workbench MUST use the Workbench Brand Information and the Workbench Recipient User Identifier for every preview and Test Delivery.
- FR-042: Test Delivery MUST deliver to Mailpit only.

Unsubscribe processing:

- FR-043: A valid GET Unsubscribe request MUST be processed immediately.
- FR-044: A valid POST Unsubscribe request MUST be processed immediately.
- FR-045: An Unsubscribe request MUST NOT require login.
- FR-046: An Unsubscribe request MUST NOT require a confirmation step.
- FR-047: Processing an Unsubscribe request MUST set the marketing consent value of the Consent Record of the Recipient User Identifier to false.
- FR-048: Processing an Unsubscribe request MUST create the Consent Record when it does not exist.
- FR-049: The marketing consent value MUST be stored as a boolean.
- FR-050: The Package MUST fire the Unsubscribe Event once per Unsubscribe request that changes the marketing consent value from true or from no Consent Record to false.
- FR-051: The Package MUST NOT fire the Unsubscribe Event when the marketing consent value is already false.
- FR-052: A valid GET Unsubscribe request MUST show SCR-002 in Success state, including when the marketing consent value is already false.
- FR-053: A valid POST Unsubscribe request MUST respond with a success HTTP status, including when the marketing consent value is already false.

Automated checks:

- FR-054: For every combination of Mail Kind and Sample Body, the Mailpit HTML check MUST report zero features with no support in any mail client it evaluates.
- FR-055: For every combination, the automated checks MUST verify FR-005, FR-006, FR-033, FR-034, and FR-035.
- FR-056: For every Advertising Mail combination, the automated checks MUST verify FR-025, FR-013, FR-021, FR-022, and FR-036.
- FR-057: For every Informational Mail combination, the automated checks MUST verify FR-011, FR-023, FR-024, and FR-037.
- FR-058: For every combination, the automated checks MUST compare the HTML part and the TEXT part with the previously approved HTML part and TEXT part of the same combination.
- FR-059: The automated checks MUST exit with code 0 only when every check passes.

Recipient Display Name:

- FR-060: The Package MUST make the Recipient Display Name available to the Mail Body.
- FR-061: The Recipient Display Name MUST be the Recipient Name followed by `님` when Recipient Name is supplied, and `회원님` when it is not supplied.

## User Flows [UNVERIFIED]

- FLOW-001: Apply to a Service
  - Install the Package in the Service -> the Service can render mail with the Package.
  - Optionally set Brand Information in environment variables or in the configuration file -> Rendered Mail shows the values. Service Name and Logo not set show Placeholders. Footer fields not set are not shown.
  - Write a Mail Body in Markdown, declare Mail Kind per mail, supply Recipient User Identifier for Advertising Mail, and optionally supply Recipient Name -> the Recipient receives a mail with an HTML part and a TEXT part, and for Advertising Mail an Unsubscribe Link.
- FLOW-002: Verify the Theme in the Workbench
  - Open SCR-001 in a browser -> SCR-001 is in Initial state.
  - Change EL-001 to EL-004 -> EL-005, EL-006, and EL-007 update.
  - Type an address in EL-008 and activate EL-009 -> EL-010 shows the result.
  - Activate EL-011 -> the Mailpit web interface opens.
- FLOW-003: Run automated checks
  - Run the automated checks -> one result line per combination is output and the exit code is set.
- FLOW-004: Recipient unsubscribes from the mail footer
  - Open the Unsubscribe Link in the Advertising Mail footer -> SCR-002 is shown in Success state, the marketing consent value is false, and the Unsubscribe Event is fired.
- FLOW-005: Recipient unsubscribes from the mail client control
  - Use the unsubscribe control of the mail client -> the mail client sends a POST request to the Unsubscribe Link, the marketing consent value is false, and the Unsubscribe Event is fired.

## Error Conditions [UNVERIFIED]

- ERR-001: Advertising Mail is rendered without Recipient User Identifier. Rendering MUST fail. The error MUST name Recipient User Identifier. No mail MUST be delivered.
- ERR-002: One or more Brand Information fields are not supplied. Rendering MUST succeed. Service Name and Logo MUST use their Placeholders. The other fields MUST NOT be shown (FR-003 to FR-008).
- ERR-003: An Unsubscribe request carries an altered or unsigned Unsubscribe Link. The marketing consent value MUST NOT change. The Unsubscribe Event MUST NOT be fired. A GET request MUST show SCR-002 in Error state. A POST request MUST respond with a non-success HTTP status.
- ERR-004: A Recipient User Identifier is supplied for an Informational Mail. Rendering MUST succeed. The Unsubscribe Link and the List-Unsubscribe headers MUST NOT be added.
- ERR-005: Mailpit is unreachable during Test Delivery. EL-010 MUST show failed. EL-010 MUST show ERR-005. No retry MUST occur.
- ERR-006: EL-008 holds an invalid email address. EL-009 MUST be disabled.
- ERR-007: An automated check fails. The output line of its combination MUST show fail. The exit code MUST be non-zero.

## Non-Goals

- Providing more than one Theme, or a way to select a Theme.
- Providing Mail Body templates for particular purposes (welcome, receipt, verification code, and so on). The Service writes its own Mail Bodies.
- Copying a Theme into a Service.
- Sending terms-change notification mails.
- Restoring a marketing consent value to true after an unsubscribe.
- Collecting prior consent for Advertising Mail.
- Restricting sending hours.
- Sending mail to Recipients from a Service.
- Delivering mail to real Recipients from the Workbench.
- Blocking or filtering Rendered Mail or mail delivery by the marketing consent value.
- Writing Mail Body wording.
- Warning or failing when a Placeholder is used, or when an optional footer field is not supplied.
- Placing a greeting in the layout. The Mail Body wording uses the Recipient Display Name.
- Calendar or event data for mail clients (attachments, structured data).
- Verifying Kakao webmail by automated checks.

- AC-006: ERR-001. Pass when Advertising Mail rendered without Recipient User Identifier fails and the error names it.

- AC-008: FR-021, FR-022. Pass when Advertising Mail contains both headers with the specified values.
